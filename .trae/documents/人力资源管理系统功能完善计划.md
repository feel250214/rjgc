# 人力资源管理系统功能完善计划

## 一、当前项目现状分析

**已实现功能**：
- 员工登录认证
- 员工信息的增删改查（CRUD）
- 员工分页查询

**当前项目架构**：
- 采用Spring Boot 3.1.0框架
- 分层架构：Controller层、Service层、DAO层
- 实体与DTO分离，使用Converter转换
- JPA + MySQL数据持久化

## 三、功能完善计划

### 1. 基础数据管理模块

**部门管理**
- 实体类：Department
- 主要字段：id、name、description、createTime
- API接口：
  - GET /departments：获取所有部门
  - GET /departments/{id}：根据ID获取部门
  - POST /departments：创建部门
  - PUT /departments/{id}：更新部门
  - DELETE /departments/{id}：删除部门

**职位管理**
- 实体类：Position
- 主要字段：id、name、departmentId、description、createTime
- API接口：
  - GET /positions：获取所有职位
  - GET /positions/{id}：根据ID获取职位
  - POST /positions：创建职位
  - PUT /positions/{id}：更新职位
  - DELETE /positions/{id}：删除职位

### 2. 员工信息管理模块完善

**员工异动管理**
- 实体类：EmployeeTransfer
- 主要字段：id、employeeId、transferType（入职/离职/调动）、transferDate、reason、createTime
- API接口：
  - GET /employee-transfers：获取所有异动记录
  - GET /employee-transfers/{id}：根据ID获取异动记录
  - POST /employee-transfers：创建异动记录
  - PUT /employee-transfers/{id}：更新异动记录
  - DELETE /employee-transfers/{id}：删除异动记录

### 3. 薪酬管理模块

**薪资管理**
- 实体类：Salary
- 主要字段：id、employeeId、basicSalary、bonus、deduction、totalSalary、month、createTime
- API接口：
  - GET /salaries：获取所有薪资记录
  - GET /salaries/{id}：根据ID获取薪资记录
  - GET /salaries/employee/{employeeId}：根据员工ID获取薪资记录
  - POST /salaries：创建薪资记录
  - PUT /salaries/{id}：更新薪资记录
  - DELETE /salaries/{id}：删除薪资记录

**福利管理**
- 实体类：Welfare
- 主要字段：id、name、description、createTime
- 实体类：EmployeeWelfare
- 主要字段：id、employeeId、welfareId、amount、grantDate、createTime
- API接口：
  - GET /welfares：获取所有福利类型
  - GET /employee-welfares：获取员工福利记录
  - POST /employee-welfares：发放员工福利

### 4. 考勤管理模块

**考勤记录**
- 实体类：Attendance
- 主要字段：id、employeeId、checkInTime、checkOutTime、attendanceDate、status（正常/迟到/早退/缺勤）
- API接口：
  - GET /attendances：获取考勤记录
  - GET /attendances/employee/{employeeId}：根据员工ID获取考勤记录
  - POST /attendances：创建考勤记录
  - PUT /attendances/{id}：更新考勤记录

**请假管理**
- 实体类：Leave
- 主要字段：id、employeeId、leaveType（年假/病假/事假）、startDate、endDate、reason、status（待审批/已批准/已拒绝）
- API接口：
  - GET /leaves：获取请假记录
  - GET /leaves/employee/{employeeId}：根据员工ID获取请假记录
  - POST /leaves：提交请假申请
  - PUT /leaves/{id}/approve：批准请假
  - PUT /leaves/{id}/reject：拒绝请假

### 5. 绩效管理模块

**绩效评估**
- 实体类：Performance
- 主要字段：id、employeeId、evaluateDate、score、grade、comment、evaluatorId
- API接口：
  - GET /performances：获取绩效评估记录
  - GET /performances/employee/{employeeId}：根据员工ID获取绩效评估记录
  - POST /performances：创建绩效评估
  - PUT /performances/{id}：更新绩效评估

**绩效统计**
- API接口：
  - GET /performances/stats/department：部门绩效统计
  - GET /performances/stats/position：职位绩效统计

### 6. 培训管理模块

**培训计划**
- 实体类：TrainingPlan
- 主要字段：id、title、description、startDate、endDate、location、trainer
- API接口：
  - GET /training-plans：获取培训计划
  - POST /training-plans：创建培训计划
  - PUT /training-plans/{id}：更新培训计划
  - DELETE /training-plans/{id}：删除培训计划

**培训记录**
- 实体类：TrainingRecord
- 主要字段：id、employeeId、trainingPlanId、attendStatus、score、comment
- API接口：
  - GET /training-records：获取培训记录
  - GET /training-records/employee/{employeeId}：根据员工ID获取培训记录
  - POST /training-records：创建培训记录
  - PUT /training-records/{id}：更新培训记录

### 7. 系统管理模块

**角色管理**
- 实体类：Role
- 主要字段：id、name、description、createTime
- API接口：
  - GET /roles：获取所有角色
  - POST /roles：创建角色
  - PUT /roles/{id}：更新角色
  - DELETE /roles/{id}：删除角色

**权限管理**
- 实体类：Permission
- 主要字段：id、name、code、description、createTime
- 实体类：RolePermission
- 主要字段：id、roleId、permissionId
- API接口：
  - GET /permissions：获取所有权限
  - POST /role-permissions：分配角色权限
  - DELETE /role-permissions：取消角色权限

**用户管理**
- 已部分实现（当前的Employee可作为系统用户）
- 需要添加角色关联

## 四、实现优先级

按照依赖关系和重要性，建议按照以下优先级实现：

1. **基础数据管理**（部门、职位）- 优先级：高
2. **系统管理**（角色、权限）- 优先级：高
3. **员工异动管理** - 优先级：中
4. **考勤管理**（考勤记录、请假）- 优先级：中
5. **薪酬管理**（薪资、福利）- 优先级：中
6. **绩效管理**（绩效评估、统计）- 优先级：低
7. **培训管理**（培训计划、记录）- 优先级：低

## 五、技术实现要点

1. **保持现有架构风格**：继续使用分层架构，实体与DTO分离，使用Converter转换
2. **数据库设计**：合理设计表关系，使用JPA注解定义关联
3. **API设计**：遵循RESTful风格，统一响应格式
4. **权限控制**：基于角色的访问控制（RBAC）
5. **事务管理**：在Service层添加@Transactional注解
6. **异常处理**：统一异常处理机制
7. **日志记录**：关键操作添加日志
